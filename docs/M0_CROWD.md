# M0 — 군중 1,000 개체 측정 계획 (2026-10-08)

`docs/DESIGN.md` §1 의 관문을 **어떻게 잴 것인가**. 재는 방법이 틀리면 그 위에 쌓는 것이 전부 틀리므로,
숫자를 뽑기 전에 이 문서를 먼저 닫는다.

> **이 문서가 답해야 하는 질문은 하나다**: *군중을 어떤 방식으로 그려야 1,000 개체가 기기에서 도는가.*
> "도는가" 가 아니라 **"어떤 방식으로"** 인 것이 중요하다 — 전자는 예/아니오지만 후자는 **선택**이고,
> 그 선택이 아트 파이프라인(리그·클립·굽기)을 정하므로 아트보다 먼저 닫혀야 한다.

---

## 1. 재는 기기

```
SM-G991N (갤럭시 S21) · Exynos 2100 · Mali-G78 MP14 · RAM 7.2 GB · 1080×2400 · Android 15
```

**이것은 설계안이 가정한 "저가 안드로이드" 가 아니다.** 2021 년 플래그십이고, 지금 붙어 있는 유일한
기기다. 그래서 통과 조건은 *"여기서 30 fps"* 가 될 수 없다 — 그 수는 보급기에서 도는 것을 증명하지
않는다. 대신 **프레임 예산의 몫**으로 잡고 배율로 환산한다 (§4).

> ⚠ **배율은 추정이다.** S21 의 GPU 가 보급기(2023 년 Snapdragon 4 급)의 3~4 배라는 것은 자료에서
> 온 수이고 **측정값이 아니다**. 싼 폰이 생기면 **그 배율부터 실측으로 바꾼다** — 그때까지 §4 의
> 8 ms 는 *"근거 있는 임시값"* 이다. 오너께 기기 여부를 여쭌 상태.

## 2. 비교할 방식 둘

같은 장면에서 **나란히** 재지 않으면 비교가 아니다 — 기기 상태(온도·백그라운드)가 두 측정 사이에
변하면 그 차이가 방식의 차이로 보인다. 그래서 **한 빌드 안에서 모드를 바꿔** 번갈아 잰다.

| | **A. 유닛마다 `Animator`** | **B. 인스턴싱 + 정점 애니메이션 텍스처(VAT)** |
|---|---|---|
| 그리는 법 | `SkinnedMeshRenderer` 1,000 개 | `Graphics.RenderMeshIndirect` · 메시 하나 · 머티리얼 하나 |
| 애니메이션 | `Animator` 가 본을 돌린다 | 정점 위치를 **텍스처에 구워** 셰이더가 읽는다 |
| 유닛당 CPU | 본 평가 + 스킨닝 (비싸다) | 거의 0 (좌표·상태만) |
| 드로우 콜 | 1,000 (배칭 거의 안 됨) | **1** |
| 비용 | 공짜 — 그냥 프리팹 | 굽는 도구 + 셰이더를 만들어야 한다 |
| 바꾸는 것 | 없음 | **아트 파이프라인** — 클립을 굽는 단계가 생긴다 |

**왜 이 둘인가**: A 는 "그냥 만들면 이렇게 된다" 는 기준선이고, B 는 이 장르가 실제로 쓰는 방식이다.
A 가 통과하면 B 를 만들 이유가 없고 (굽는 도구 + 셰이더가 공짜가 아니다), A 가 떨어지면 **B 가
얼마나 버는지**가 설계를 정한다. 중간 선택지(`BatchRendererGroup`·GPU 스킨닝)는 **A 가 떨어지고
B 가 통과한 뒤에** 볼 자리다 — 지금 셋을 재면 어느 것도 제대로 못 잰다.

**캡슐로는 재지 않는다.** `DESIGN.md` §1 이 *"캡슐 하나로 충분하다"* 였고 그것이 §3.0 에서 고쳐졌다 —
캡슐 1,000 개가 도는 것은 **트랜스폼과 드로우 경로가 멀쩡하다**는 뜻일 뿐이다. 출하할 군중은
스킨드 + 애니메이션이고 자릿수가 다르다. 캡슐은 **1 주차 배선 확인용**으로만 쓴다.

## 3. 무엇을 숫자로 남기는가

프레임률(fps)은 **평균이라 최악을 숨긴다.** 드래그 입력 게임에서 한 번의 긴 프레임은 평균 5 fps
손실보다 더 나쁘게 느껴지므로, 남기는 것은 **프레임 시간의 분포**다.

| 수 | 왜 |
|---|---|
| CPU 프레임 중간값 (ms) | 계산이 무거운가 |
| GPU 프레임 중간값 (ms) | 그리는 것이 무거운가 — **둘을 갈라야** 어느 쪽을 고칠지가 정해진다 |
| **p99 프레임 (ms)** | 증식 순간. *"눈에 띄는 멈춤 없음"* 을 수로 바꾼 것 |
| 드로우 콜 · SetPass | 방식 B 가 실제로 1 로 줄었는지 |
| **프레임당 관리 힙 할당 (B)** | 0 이어야 한다. GC 한 번이 p99 를 혼자 망친다 |
| 상주 메모리 기울기 (10 분) | 새는가 |
| 기기 온도 / 클럭 | **스로틀링** — 10 분 뒤의 수가 1 분 뒤의 수와 다르면 그 차이가 방식 차이로 보인다 |

### 측정의 함정 셋 (먼저 막는다)

1. **vsync 가 비용을 가린다.** S21 은 120 Hz 다. vsync 가 켜져 있으면 프레임 시간이 8.3 ms 단위로
   양자화되어, 군중이 4 ms 를 써도 **8.3 ms 로 읽힌다** — 그러면 A 와 B 가 같은 수로 나온다.
   → `QualitySettings.vSyncCount = 0` · `Application.targetFrameRate = -1` 로 **풀어 놓고** 잰다.
   그 상태의 프레임 시간이 *실제 비용*이고, 예산과 비교할 수 있는 유일한 수다.
2. **빈 장면에서 재면 예산을 전부 쓴다.** M0 에는 UI·VFX·사운드·지형·게이트·전투 규칙이 하나도
   없다. 그래서 통과선은 *"프레임에 들어온다"* 가 아니라 **"프레임의 절반 안에 들어온다"** 다 (§4).
   유닛당 계산의 자리도 비워 두면 안 되므로, **더미로 유닛당 O(n) 한 번**을 넣고 잰다 —
   M1 의 전투가 붙을 자리를 지금 예산에 포함시킨다.
3. **첫 30 초는 버린다.** 셰이더 워밍업·텍스처 업로드·JIT 가 섞인다. 측정 창은 **30 초 뒤부터
   60 초**, 그리고 스로틀링을 보려고 **9~10 분 구간**을 한 번 더 찍는다.

## 4. 통과 조건

```
M0 통과 — SM-G991N 에서, vsync 해제, 아군 500 + 적 500 = 1,000 개체
 · 출하할 방식 그대로 그린다 (애니메이션 포함 · 캡슐 아님)
 · 군중(그리기 + 유닛당 더미 계산)이 프레임의 ≤ 8 ms
 · p99 프레임 ≤ 중간값 × 2  — 증식 프레임 포함
 · 군중 경로의 프레임당 관리 힙 할당 = 0 B
 · 9~10 분 구간의 중간값이 0.5~1.5 분 구간의 1.3 배 이내 (스로틀링)
 · 상주 메모리 기울기 ≈ 0
```

**8 ms 의 산수**: 보급기가 S21 의 1/3~1/4 이라면 거기서 24~32 ms — 겨우 30 fps 이고, **그것도 아직
아무것도 안 붙은 상태**다. 그리고 8 ms 는 16.6 ms 의 절반이라 **M0 가 담지 않은 전부에 나머지
절반**을 남긴다. 숫자는 움직여도 되지만 **"예산의 몫 + 꼬리값"** 이라는 모양은 지킨다.

**떨어졌을 때**: 설계안 §1 의 대안(개체를 수로만 들고 화면은 추상화)으로 간다. `Core/` 가 개체
하나의 정체성을 전제하지 않게 써 두었으므로(세션 A 확인) **로직은 그대로 선다.**

## 5. 에디터 창을 띄우지 않고 재는 방법

> 오너 2026-10-08 (~10-11): *"유니티 확인하는 건 모니터 안 보이게 해야 해. 계속 켜 두지 말고
> 확인했으면 꺼."* M0 는 원래 **실기 측정**이라 이 규칙과 부딪히지 않는다 — 에디터가 아니라 폰에서
> 돌고, 빌드는 배치 모드다.

```
1. 빌드      Unity -batchmode -nographics -quit -executeMethod M0Build.Android
2. 설치·실행  adb install -r Builds/M0.apk ; adb shell am start -n <pkg>/com.unity3d.player.UnityPlayerActivity
3. 거두기    adb logcat -s Unity | <M0 줄만>        ← 수는 전부 로그로 나온다
4. 끈다      adb shell am force-stop <pkg> · Unity 프로세스 잔존 확인
```

- **화면을 봐야 하는 것**(군중이 제대로 그려지나·애니메이션이 도나)은 **`adb exec-out screencap`** 으로
  뽑는다. 에디터도, 오너 모니터도 쓰지 않는다.
- 측정 결과는 **표 하나**로 이 문서 §6 에 적는다 — 두 방식을 나란히 놓은 그 표가 M0 의 산출물이다.
